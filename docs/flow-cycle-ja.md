# Process / Recovery と Join / Fork

設備の基本サイクルは次の接続です。Details → Flow の Add プルダウンから **Join** と **Fork** を追加できます。

```text
inPort → Join → Process → Fork → outPort
           ↑               ↓
           └── Recovery ←──┘
```

- **Process time**：前工程から受け取り開始～後工程待ち。Process が終了しても後工程が受け取れない間は待機します。
- **Recovery time**：後工程へ搬送開始～前工程待ち。後工程が実際に受け取った時刻から計測します。後工程待ちの間には進みません。
- **Join**：すべての入力が揃ったら出力します。基本サイクルでは入力1がワーク、入力2が Recovery 完了です。Recovery 中は前工程からの受け取りを止めます。
- **Fork**：すべての出力を同時に発火します。基本サイクルでは出力1が outPort へ、出力2が Recovery へ接続され、実際の搬送開始時に両方が進みます。

例えば Process 2秒・Recovery 3秒なら、時刻0秒に受け取ったワークを最短2秒で搬送し、5秒に次の受け取りが可能になります。後工程が10秒まで受け取れなければ、搬送は10秒、Recovery 完了は13秒です。後工程の Process と前工程の Recovery は並行して進みます。

## 接続と初回起動

ワークの接続は実線、完了信号の接続は紫色の破線で表示します。Fork の出力の種類は接続先から決まり、番号の順番には依存しません。outPort へ向かう出力はワーク、Recovery や Join の追加入力へ向かう出力は完了信号です。複数の Entity の格納には Palletizing を使います。

**Fork のワーク出力が複数ある場合は、各出力へ別の個体を同時に送ります。** 例えば、画像のように `Fork1 → Fork2 → 6つの outPort` とつなぐと、1個のワークが合計6個になります。1つの出力では元の個体を使い、残り5個には新しい個体IDを発行します。属性と内包するワークも、それぞれ独立した個体として複製します。Entity Type は増やしません。

outPort へ続く Fork / entityRouter の連なりでは、全出力の後工程が受け取れるまで待ちます。待機中には複製も部分出力も行わず、全出力の搬送と Recovery を同じ時刻に開始します。Fork のノード内には、受け取り可能な出力数も表示します。通常の「outPort 1本＋Recovery 1本」のサイクルは、ワークを増やしません。

ノード本体の右クリックメニューで Join の入力、Fork の出力、entityRouter の入出力を増減できます。`Remove inPort` / `Remove outPort` は末尾のポートと接続線を削除します。Join の入力は2個、Fork の出力は2個、entityRouter の入出力は各1個を最小として残します。実行中の変更には Reset が必要です。複数の Recovery を Fork から開始した場合、Join はすべての完了を待ちます。

### 線の接続・付け替え

- メイン画面と同様、ノード左右の丸いポートからドラッグして接続します。接続先の丸から画面上で28px以内にドロップすると吸着します。
- 接続済みの入力ポート、または線そのものをドラッグすると、その線の接続先を付け替えられます。空の入力から出力への接続も可能です。接続済み入力の接続元を変更したい場合は Shift を押しながらドラッグします。
- ポートを2回クリックして接続先を選ぶ操作にも対応しています。
- 接続済みポートへつなぐと、そのポートの古い線を新しい線に置き換えます。接続が確定するまでは元の線を保持します。
- ドラッグ中は仮の線と接続候補を表示します。空白へのドロップや Esc は取り消しです。
- 線をクリックして選択し、Delete / Backspace で切断できます。線またはポートの右クリックでも切断できます。
- 実行中のワークや Recovery がある設備は Reset 後に配線を変更してください。停止中の空の Flow を編集しても、それだけで処理は開始しません。

パネルの高さ変更や別ウィンドウからの復帰時には自動で全体を収めます。手動でズーム・移動した場合はその表示を維持し、Fit All で自動フィットに戻せます。
接続点が小さい場合は **Expand Flow** で画面いっぱいに広げるか、**100%** / **＋・−** で編集しやすい倍率に変更してください。Close expanded view で下部パネルに戻ります。

### ノード内の実行状態

タイトル部分はメイン画面と同じ状態色で表示します。各ノード内には次の情報を表示します。

| ノード | 表示内容 |
|---|---|
| Process / Recovery | Elapsed（経過時間）、Remaining（残り時間）、時間条件の成立、進捗バー |
| Join | 入力ごとの Ready / Waiting、成立数 / 必要数 |
| Fork | 入力成立、後工程待ち、同時発火した最終時刻 |
| syncroJudgment | 同期グループの準備完了数 / メンバー数、条件成立 |
| Palletizing / DePalletizing | 親の受信、格納数 / 容量、残り内容物数 |
| entityRouter | 選択先、または Round robin の次の出力 |

完了した Process / Recovery は DONE と直近の所要時間を表示します。Last fired は直近に出力したシミュレーション時刻です。進捗と条件の表示は読み取り専用で、画面を開いても処理を進めません。停止中は時間表示も停止し、Reset で実行履歴を消去します。

Recovery → Join の戻り入力は Reset 時に完了済みとして初期化し、最初のワークを受け取れるようにします。2回目以降は実際の Recovery 完了を待ちます。停止・再開、実行状態の保存・復元で残り時間と完了信号を保持します。Recovery 中に時間設定を変更した場合は、元の開始時刻から新しい時間を計算します。接続の編集には Reset が必要です。

## 既存データ

標準テンプレートと同梱サンプルをこの接続に変更しています。旧 Flow v2 の直列 `Process → Recovery → outPort` は読み込み時にも変換します。既に Join / Fork を含む独自 Flow は自動変換せず、接続検証で確認します。

Sample Line2 は119設備のサイクルを変更し、設備間の接続・処理時間・復帰時間・4種類の Entity Types を維持しています。構成は [Sample Line2](sample-line2-ja.md) を参照してください。
