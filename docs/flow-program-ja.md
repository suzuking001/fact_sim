# 実行 Flow エディタ

Details → Flow を開くと、現在の処理をその場で編集できます。設備の標準処理では、実際の受付順・搬送・同期を表示し、時間・条件・対象ワークを下書きとして編集します。自由配線を適用済みの設備では、保存されたノード・配線を直接編集します。どちらも「Flow を適用」で反映し、編集用の別画面へ移動する必要はありません。

標準処理の内部配線は専用コントローラで固定です。別の処理順を一から組む場合だけ「配線メニュー → 新しい配線を一から作る」を使います。未適用の設定がある場合は先に適用または破棄します。既存の自由配線がある場合は「保存した配線を読み込む」、編集中の配線がある場合は「未適用の配線を続ける」と表示します。以下は自由配線の操作です。

## 操作

1. 「ノード追加」で必要な処理・条件分岐・条件待ちを追加します。
2. 「次へ」から次のノードの「前から」へドラッグして処理順をつなぎます。ワーク用の線を別に接続する必要はありません。条件分岐の出口は「はい／いいえ」です。
3. ノードを選び、時間、対象ワークを編集します。受け取る入口・送り出す出口は INPUT / OUTPUT の設定で選びます。「条件分岐」「条件待ち」の設定欄では、条件を行として追加・編集できます。
4. Reset 後に「Flow を適用」を押します。接続不備は適用前に表示します。

新しい配線を未適用の間は「配線メニュー → 現在の処理に戻る」で元の処理に戻れます。編集中の配線は保持されます。適用済みの自由配線から標準処理へ戻す場合は「配線メニュー → 設備の標準処理に戻す」を使います。この操作には Reset が必要です。

編集中の「元に戻す／やり直す」は未適用の配線に作用します。適用後はアプリ全体の Undo／Redo でも戻せます。JSON に `properties.flowProgram` として保存され、再読込でも復元します。既存設備の標準処理の設定は残ります。

初期テンプレートは最初の入出力を使う新規の簡単な Flow です。Merge、搬送、同期、独自スクリプトの自動変換ではありません。適用するまで実際の設備動作は変わりません。実行中は編集をロックします。

## 通常表示と詳細表示

通常表示では、処理順を中心に表示し、条件ノードと紫の条件線を設定欄へまとめます。条件の要約はノード上に表示され、選択すると全文を確認できます。「すべて満たす」「どれかを満たす」「満たさない」で条件を組み合わせ、「条件の追加・組み合わせ」で入れ子を作れます。1グループの接続は最大4条件です。さらに必要な場合は条件をグループで包んで追加します。

「詳細表示」では元の条件ノード・条件線を直接編集できます。表示の切り替えは未適用の配線やUndo履歴を保ち、保存設定を変更しません。通常表示の配置は表示用で、保存されている詳細配線の位置を上書きしません。

共通の条件には使用先を表示し、編集はすべての使用先に反映します。条件を外す操作は選択した参照を解除し、他で使われていない条件だけを削除します。AND／ORから条件を外して1件になった場合は、その条件にまとめます。設備の分岐・待機ノードを削除した場合、残った条件は「未接続の条件」として表示します。不正な条件は所有ノードと設定欄に表示され、詳細表示で接続を修正できます。

## 処理と条件

| ノード | 動作 |
|---|---|
| INPUT | 指定した設備ポートから1件受け取る。対象種別を指定可能 |
| Process / Recovery | 設定した時間待つ |
| OUTPUT | 保持中の先頭1件を搬出し、接続先の受渡完了後に次へ進む |
| 並列開始 | 接続した経路を同時に開始する |
| 全経路の完了を待つ | 接続された全経路の到達を待つ |
| 到着ごとに進む | 到達した経路ごとに次へ進む。重複経路のキャンセルはしない |
| 条件分岐 | 条件結果で true / false のいずれかへ進む |
| 条件待ち | 条件が成立するまで待機する |
| 条件 / AND / OR / NOT | ワーク有無・種別・属性・個数・ID一致・容量条件を組み合わせる |
| ワーク生成・消滅・複製 | 保持ワークを追加・消費・複製する |
| ID照合・ワーク統合 | 全保持ワークのID一致を確認し、最初の1件へ統合する |
| END | 経路を終了。全経路の終了後、次のサイクルをSTARTから開始する |

「INPUT → Process → INPUT → OUTPUT」も設定できます。複数の保持ワークは並列経路を含めてサイクル全体で共有します。OUTPUT ごとの専用ワーク割り当てではありません。END までに全ワークを搬出または消滅させてください。残った場合はエラーを表示します。

条件の「ワーク種別」「属性」は先頭ワークを参照します。「個数」「ID一致」は全保持ワークを参照します。属性パスは `attributes` 内を起点とします。条件ANDと、実行経路を待つANDは別のノードです。

並列・合流・条件演算の接続口は最大4個です。必要なら複数ノードを組み合わせます。待機のない循環と、不正な接続は適用できません。条件次第で終了しない待機や、相互に到達しない経路をANDへ接続した場合は待機し続けます。

## 実行方式と対応範囲

実行 Flow を含むグラフは、全体を dt エンジンで実行します。高速エンジンを選んでも dt にフォールバックします。高速・worker エンジン向けのコンパイル、信号制御、専用搬送・同期動作の自動変換は未対応です。

Recovery は配線位置どおりに実行します。OUTPUT の後へ置いた場合は受渡完了後に開始します。従来動作にある搬出と Recovery の重なりを自動再現するものではありません。
