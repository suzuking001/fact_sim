# Details の Flow

実際の処理順を配線で変更する場合は「配線編集 · 実行 Flow を作成」を使います。操作と実行上の制約は [実行 Flow エディタ](flow-program-ja.md) を参照してください。以下は従来動作の表示モードの説明です。

Flow は、選択中の設備の実行方式と正規化済みの設定を表示する独立した LiteGraph です。この表示グラフを実行したり、保存用の実行グラフとして使用したりはしません。

## 操作

- 通常表示では条件ノードと条件線をまとめて隠し、INPUT / OUTPUT RULE に条件の要約を表示します。ルールを選ぶと、対象ワークと条件を同じ設定欄で編集できます。
- 条件は行として追加・編集・削除し、「すべて満たす／どれかを満たす／満たさない」で組み合わせます。「条件の追加・組み合わせ」から入れ子も作れます。
- 「詳細表示」で元の条件ノード・配線を表示します。以下の条件ノードを直接選ぶ操作は詳細表示で使います。表示切り替えは保存データを変更せず、配線の下書きと各表示の配置を保ちます。
- Process / Recovery を選択：下の設定欄で Flow ごとの時間を編集。
- 条件ノードを選択：条件種別、比較値、AND / OR / NOT を編集。
- INPUT / OUTPUT RULE を選択：対象ワークを編集。受付順、出力先、Sequence 方式への切り替えは固定。
- 空白をドラッグ：パン。ノードをドラッグ：表示位置の移動。ホイールまたは ＋ / −：ズーム。
- 「サイクル」「全体表示」：表示範囲を調整。「配置を戻す」：表示位置を初期化。
- 要素一覧からの選択にも対応。キャンバス上では矢印キーでパン、＋ / − でズーム、0 で全体表示。
- 説明はホバー、選択後の設定欄、または「？」で確認。
- ノード選択後の設定欄は、日本語の見出し・接続先の設備名・対象ワーク名を表示。「この設定の説明」と「条件の追加・組み合わせ」は同じ設定欄内で展開できます。
- Sequence の対象は JSON ではなく、生成順のワークと個数の行で編集できます。上へ／下へで順番を変えます。

実行中は設定編集をロックします。実行状態・待機理由・搬入済み数は内部フィールドを読み取って表示します。条件の判定関数は呼び出さず、記録された評価結果がない条件は「未評価」と表示します。

## 線の意味

| 表示 | 意味 |
|---|---|
| 灰色の破線・四角の接続口 | 実行順序 |
| 緑の実線・丸い接続口 | ワークの接続 |
| 紫の点線・ひし形の接続口 | 条件・設定の参照 |

下段は優先順に並んだ設定参照行です。並列実行の枝ではありません。ポートや実行サイクルへの長い参照線は、関連するルール・時間を選択した際に表示します。内部の配線変更には対応しません。

## 実行方式の対応

| 実行方式 | 表示の要点 |
|---|---|
| Merge | 接続入力のポート順受付、2件目以降の ID 照合、全入力後の Process、出力提示と同時開始の Recovery。不一致時の停止／リセットも表示 |
| Join | 到着順キューから1件ずつ処理。同時到着の検出順は巡回走査。OR や並列実行とは区別 |
| Equipment / Branch | 優先入力、Process、選択搬出、出力提示と重なる Recovery |
| Split | 接続先の受付確認、選択出力への複製・同時提示、Recovery と全受渡完了の両方を待機 |
| Shuttle | グループの処理完了確認、同期 TRANSFER、受渡中の次入力保持。Recovery はなし |
| Carrier Route | 搬送体受付・処理、ワークの反復搬入、ワーク／パレット搬出、搬送体搬出の専用制御。保存されたルールの対象・条件はこのランタイムでは未使用と明示 |
| AGV Route | 搬送体／ワークの受付・搬出を専用制御として表示 |
| Source | Sequence の生成候補、出力条件・下流受付、生成・提示・受渡待ち。Process / Recovery の保存値は未使用 |
| Sink | 入力条件を照合して受取・完了を記録。Process / Recovery の保存値は未使用 |
| その他・有効な独自スクリプト | 明示した内部コントローラ／独自処理ブロック。内部配線を推測しない |

Basic v2 では旧 script プロパティが残っていても `_evalScript` が任意スクリプトを実行しないため、その値だけを根拠に独自処理とは判断しません。

Carrier Route の共通時間は読込時と同じく最初のポートの正規化済み時間を参照します。編集時もその値を既存の一時的なスカラー値へ反映し、保存・再読込との一致を保ちます。

## 保存と検証

設定変更は既存の beforeChange / change / afterChange と Undo 履歴へ反映します。ノード・ルール・ポート・ステージ ID で編集対象を取り直し、条件ツリーの古い参照は拒否します。表示位置・選択・ズームはセッション内だけで保持し、JSON へ追加しません。

回帰テスト：

```powershell
cd mcp
node scripts/test-flow-view.mjs
node scripts/test-flow-settings.mjs
node scripts/test-flow-simplification.mjs
node scripts/test-flow-engines.mjs
npm run check
```

`test-flow-view.mjs` はユーザーのブラウザとは独立した MCP ランタイムを使用します。Sample Line 2 全121ノードのモデル・画面生成、表示時の判定呼出し禁止、JSON 不変性、時間と条件の編集、Undo / Redo、再読込、別ウィンドウでの線・ドラッグ、狭い画面、240秒の表示開閉差分を確認します。

結果は `artifacts/flow-view/validation.json`、画像は `tmp/flow-*.png`、Engine Test は `artifacts/engine-test/` に保存します。Sample Line 2 の240秒テストでは、現在の設定の完了数は表示あり・なしの両方で0です。ワーク接続と状態遷移の一致も別途照合します。
